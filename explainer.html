배경

AI Factory란 무엇인가

요즘 ChatGPT 같은 AI 모델을 훈련하려면 GPU 수천 개가 동시에 협력해야 합니다. 이 GPU들을 한 건물에 모아두고, 초고속 케이블로 연결하고, 전용 냉각·전력·네트워크를 깔아놓은 곳이 AI Factory(AI 팩토리)입니다.

비유

일반 데이터센터가 "다용도 오피스 빌딩"이라면, AI Factory는 반도체 공장입니다. 같은 제품(AI 계산)을 대량으로 찍어내도록 공간·설비·물류가 최적화된 전용 시설.

문제는 이 안에 GPU 수천 개, 스위치 수백 대, 케이블 수만 개가 있다 보니 어느 장비에 무슨 설정이 되어 있는지 일일이 손으로 관리하는 게 사실상 불가능하다는 점입니다. 그래서 자동화된 구성 관리 시스템이 필요합니다.

핵심 개념

세 가지 키워드: Desired State · Drift · Reconcile

이 문서에 나오는 모든 시스템은 사실 이 세 개념의 반복입니다. 먼저 이것만 이해하면 나머지는 자연스럽게 따라옵니다.

① Desired State (원하는 상태)

"장비가 이래야 한다는 설정을 파일로 적어두는 것"
비유

에어컨 리모컨에 22℃를 맞춰두는 것. 에어컨은 현재 온도가 뭐든 상관없이 22℃가 될 때까지 계속 조절합니다. 내가 원하는 상태(22℃)를 선언하면 기계가 알아서 맞춥니다.

네트워크 스위치에 "포트 A는 100Gbps, VLAN 10번을 써야 한다"고 파일에 적어두면, 시스템이 알아서 스위치에 그 설정을 적용합니다. 이 파일이 Source of Truth(진실의 원천)입니다.

② Drift (표류)

"원하는 상태 ≠ 실제 상태인 상황"
비유

기숙사 에어컨을 22℃로 맞춰놨는데, 누군가 몰래 26℃로 바꿔놓은 상태. 내가 원하는 설정(22℃)과 실제(26℃)가 달라졌습니다 → Drift 발생.

네트워크에서는 담당자가 실수로 설정을 바꾸거나, 장비 재부팅 후 설정이 날아가거나, 케이블이 잘못 꽂혀서 Drift가 생깁니다. 이걸 감지하는 게 Drift Detection입니다.

③ Reconcile (교정)

"Drift를 발견했을 때 원하는 상태로 되돌리는 것"
비유

에어컨이 26℃인 걸 감지하고 자동으로 다시 22℃로 틀어주는 것. 이게 자동화된 Reconcile입니다. 또는 관리자에게 "누군가 바꿨어요" 알림만 보내고 사람이 고치게 하는 것은 반자동 Reconcile.

NVIDIA의 각 도구들은 Drift를 얼마나 자동으로 교정해주냐가 다 다릅니다. 어떤 건 경고만, 어떤 건 자동 수정까지 합니다.

전체 구조

NVIDIA DSX OS는 "관리사무소 + 전문 관리팀" 묶음

NVIDIA DSX OS는 단일 운영체제가 아닙니다. AI Factory를 운영하기 위한 오픈소스 소프트웨어 모음입니다. 마치 대형 아파트 단지의 관리 조직처럼, 각자 담당 영역이 나뉩니다.

비유 — 아파트 단지 관리 조직

관리사무소 (DSX OS 전체) — 단지 전체 운영
├ 배관·전기 관리팀 (NICo) — 네트워크 인프라 상태 점검·교정
├ 각 동 스마트 전기함 팀 (DPF) — 각 서버의 네트워크 기능 원격 제어
└ CCTV·센서 팀 (Fleet Intelligence Agent) — GPU·네트워크 상태 수집·보고

NICo
NVIDIA Infra Controller

전체 네트워크 인프라 상태를 감시하고, Drift를 감지해서 교정하는 중앙 컨트롤러. Rust + Go로 작성.

DPF
DOCA Platform Framework

각 서버에 꽂힌 BlueField DPU(스마트 네트워크 카드)에 네트워크 기능을 배포·관리하는 시스템. Go로 작성.

Fleet Intelligence Agent
텔레메트리 수집기

GPU 상태, InfiniBand 링크 품질 같은 데이터를 수집해서 보고. 시스템 설정을 바꾸지는 않고 읽기만 함.

NICo 심층

NICo가 네트워크를 관리하는 두 가지 방식

AI Factory의 네트워크는 케이블 종류에 따라 크게 두 계열로 나뉩니다. NICo는 이 두 계열을 서로 다른 방법으로 관리합니다.

고속 내부 네트워크
InfiniBand / NVLink
일반 이더넷 네트워크
Spectrum-X Ethernet
GPU끼리 직접 통신하는 초고속 전용선. 기차로 치면 KTX 전용 선로.
일반 데이터 트래픽. 기차로 치면 일반 도로.
NICo가 감시만 하고, Drift 발견 시 외부 전문 관리자(Fabric Manager API)에게 "고쳐달라"고 신고.
NICo 안의 DPU Agent가 30초마다 직접 순찰하며 설정을 읽고, 다르면 바로 고침.
비유

InfiniBand/NVLink 관리 = 아파트 엘리베이터 유지보수.
관리사무소(NICo)가 엘리베이터 상태를 모니터링하다가 이상하면 전문 유지보수 업체(Fabric Manager)를 부릅니다. 직접 분해하지 않음.

Ethernet 관리 = 아파트 복도 청소.
청소부(DPU Agent)가 30분마다 직접 돌며 확인하고, 쓰레기(Drift)가 있으면 바로 치웁니다.

DPF / DPU 심층

BlueField DPU: 서버 안의 "작은 컴퓨터"

요즘 서버에는 단순한 네트워크 카드가 아니라, 자체 CPU·메모리·OS를 탑재한 DPU(Data Processing Unit)가 들어갑니다. NVIDIA BlueField가 대표적입니다.

비유

공유기에 단순한 랜포트만 있는 게 아니라, 안에 작은 라즈베리파이가 들어가 있어서 네트워크 방화벽·VPN·QoS를 알아서 처리하는 것. 서버 CPU는 AI 계산에만 집중하고, DPU가 네트워크 잡일을 다 떠맡습니다.

DOCA Platform Framework(DPF)는 이 DPU들을 쿠버네티스로 관리하는 시스템입니다. 쿠버네티스를 처음 배우는 분들을 위해: 쿠버네티스는 컨테이너(도커 박스)를 여러 컴퓨터에 자동으로 배포·관리하는 시스템입니다.

비유 — DPF의 이중 쿠버네티스 구조

본사(Host Cluster) — 관리자가 "각 지점에 이 프로그램 설치해라"고 명령 내리는 곳.
각 지점(DPU Cluster) — 실제로 그 프로그램이 돌아가는 곳(각 BlueField DPU).

본사에서 "방화벽 설정 업데이트" 명령을 내리면, 각 지점의 DPU가 자동으로 업데이트됩니다. 관리자는 DPU 1000개를 일일이 손대지 않아도 됩니다.

DPUService: 원하는 상태를 파일로 선언

DPF에서는 "어떤 네트워크 기능을 DPU에서 실행해야 한다"는 걸 DPUService라는 설정 파일로 적습니다. 그러면 ArgoCD라는 도구가 실제 DPU 상태와 비교해서 자동으로 배포합니다.

실제 흐름

DPUService 파일 작성 → DPF Controller 감지 → ArgoCD가 Helm Chart 배포 → DPU Cluster에 적용

비유

레스토랑 메뉴판(DPUService 파일)에 "시저 샐러드는 이 재료·이 레시피로 만든다"고 적으면, 주방(ArgoCD)이 알아서 레시피대로 요리해서 손님(DPU)에게 냅니다. 셰프가 매번 직접 레시피를 외울 필요가 없습니다.

Fabric별 관리 도구

케이블 종류마다 다른 "교통 관제 시스템"

AI Factory의 네트워크는 세 종류의 케이블이 각각 다른 역할을 합니다. 마치 도로·철도·항공이 각각 다른 교통 관제를 쓰듯이, 관리 도구도 따로 있습니다.

NVUE + NetQ
Spectrum-X 이더넷 관리

NVUE: 스위치 설정을 "이래야 한다"는 파일로 선언하면 자동 적용. 4단계 상태(None → Partial → Applied → Committed)로 관리.
NetQ: "현재 토폴로지가 설계도와 맞나?" 자동 검증.

UFM
InfiniBand 관리

GPU 서버들을 연결하는 초고속 InfiniBand 망의 교통 관제센터. 13가지 자동 검증 테스트를 돌려서 Drift를 잡아냄.

NMX
NVLink 관리

GPU 8개가 한 묶음(NVLink Switch)으로 초고속 통신하는 전용선 관리자. 폐쇄된 시스템이라 자동 교정이 가능한 유일한 영역.

CVT
케이블 배선 검증

물리 케이블이 설계도대로 꽂혀 있는지 검증. Drift를 4가지로 분류: Unexpected(뜬금없음) / Stale(구식) / Missing(없음) / Intentional(의도된 변경).

비유 — NVUE 선언적 설정

스위치 설정을 예전엔 이렇게 했습니다: "포트1 열어, 포트2 닫아, VLAN 설정해, 저장해…" (절차적)
NVUE는 이렇게 합니다: "최종 결과가 이래야 한다"는 파일만 주면 알아서 차이를 계산해서 적용. (선언적)
마치 내비게이션에 목적지만 입력하면 경로는 알아서 찾아주는 것.

보조 개념

CRD가 뭔지 모르면 이것만

위에 나온 시스템들이 전부 "쿠버네티스 CRD 기반"이라고 합니다. CRD를 모르면 이후 내용이 이해가 안 가므로 간단히 설명합니다.

쿠버네티스(Kubernetes)란?

비유

도커 컨테이너(= 독립된 앱 박스)를 수백 대 서버에 자동으로 배포·재시작·확장해주는 운영체제. 혼자 10명짜리 카페를 운영할 때는 직접 관리하지만, 전국 1000개 체인이 되면 본사 시스템이 필요함 — 그게 쿠버네티스.

CRD(Custom Resource Definition)란?

비유

쿠버네티스에는 기본으로 "Pod(컨테이너 단위)", "Service(네트워크 엔드포인트)" 같은 오브젝트 타입이 있습니다. CRD는 내가 새 타입을 정의하는 것입니다.

예를 들어 NVIDIA가 DPUService라는 CRD를 만들면, 쿠버네티스가 그걸 인식하고 관리해줍니다. 마치 엑셀에서 기본 서식 외에 내가 새 템플릿을 만드는 것과 같습니다.

DPF의 주요 CRD들

DPUSet — "이 DPU 묶음에 이 OS를 깔아라"
DPUService — "이 네트워크 기능을 DPU에서 실행해라"
DPUServiceChain — "패킷이 A 기능 → B 기능 → C 기능 순서로 처리되도록 체이닝해라"

Controller/Operator 패턴이란?

비유

내가 에어컨 리모컨(CRD 파일)에 "22℃"를 설정하면, 에어컨 내부 온도 조절 회로(Controller)가 계속 현재 온도를 체크하면서 22℃가 되도록 조절합니다. 내가 "지금 몇 도야? 몇 도 내려야 해?" 계산할 필요 없이 목표만 선언하면 됩니다.

쿠버네티스 Controller도 똑같습니다: "원하는 상태" 파일을 보고, "실제 상태"와 비교하고, 다르면 자동 교정. 이 무한 루프가 Reconcile Loop입니다.

AIPub 적용

이걸 AIPub 플랫폼에 어떻게 쓸 수 있나

AIPub은 여러 팀(테넌트)이 GPU 자원을 나눠 쓰는 ML 플랫폼입니다. 각 팀에게 격리된 네트워크 공간을 주고, 그 설정을 자동으로 관리하는 것이 목표입니다.

비유 — 대학교 강의실 예약 시스템

리소스 그룹(ResourceGroup CR) = 강의실
NetworkPolicy = 강의실 출입 카드 규칙 ("이 강의실엔 이 수업 수강생만 들어올 수 있음")
resource-group-controller = 카드 규칙을 자동으로 발급·갱신하는 시스템

교수님이 "이 강의실은 컴공 3학년 전용"이라고 선언하면, 시스템이 알아서 카드 접근 권한을 설정하고, 누군가 무단 접근하면 경보를 올립니다.

구체적으로 무엇을 추가하나

현재 AIPub이 자동 관리하는 것
추가로 자동 관리할 수 있는 것
Namespace, RBAC, ResourceQuota, Secret
NetworkPolicy (네트워크 격리 규칙)
팀별 CPU·메모리 할당량
팀별 네트워크 대역폭·QoS 정책
팀 생성 시 자동 프로비저닝
설정 Drift 감지 + dry-run으로 "변경 미리보기"

NVIDIA의 CVT가 케이블 Drift를 4가지로 분류하듯이, AIPub도 NetworkPolicy Drift를 분류해서 보고할 수 있습니다:

Drift 분류 예시 (CVT 패턴 차용)

Unexpected: 설정 파일에 없는 NetworkPolicy가 클러스터에 존재 → 누가 몰래 추가했나?
Missing: 설정 파일에 있어야 할 규칙이 클러스터에 없음 → 삭제됐거나 적용 실패
Stale: 이미 삭제된 팀의 NetworkPolicy가 남아있음 → 정리 필요
Intentional: 변경 이력이 있음 → 정상 변경, 무시해도 됨

핵심 경계 — NVIDIA vs AIPub이 각각 담당하는 것

Desired State 원해야 하는 최종 상태 선언 에어컨 목표 온도
Drift 원하는 상태 ≠ 실제 상태 누가 에어컨 온도 바꿔놓음
Reconcile Drift를 원하는 상태로 되돌리기 에어컨이 자동 복구
CRD 쿠버네티스에 새 오브젝트 타입 추가 엑셀에 새 서식 만들기
DPU 서버 안의 작은 컴퓨터(스마트 NIC) 공유기 속 라즈베리파이
InfiniBand GPU 전용 초고속 네트워크 KTX 전용 선로
NVLink GPU 8개 묶음 내부 전용 연결 방 안의 내선 전화
NVUE 스위치 설정을 선언적으로 관리 목적지 입력하면 경로 찾는 내비
ArgoCD 설정 파일이 바뀌면 자동 배포 자동 업데이트 알림 + 설치
NetworkPolicy 어떤 Pod가 어떤 Pod와 통신할 수 있는지 규칙 강의실 출입 카드 규칙
