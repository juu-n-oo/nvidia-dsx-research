01개요

NVCM이란 NVIDIA Config Manager

대규모 데이터센터 네트워크를 위한 오픈소스 자동화·구성 관리 플랫폼. k8s 위 Helm으로 배포되는 이벤트 기반 마이크로서비스.

  • 단일 진실 공급원 — Nautobot에 디바이스·IP·케이블·인벤토리 집약
  • 선언 → 자동 렌더 — SoT가 바뀌면 이벤트 발생, 템플릿으로 config 자동 생성 (수작업 CLI 제거)
  • Zero-Touch 프로비저닝 — DHCP→ZTP로 부팅·OS·설정 무인 전달
  • 승인 워크플로 + 불변 이력 — Temporal 승인 게이트 · 버전 diff·롤백
현재 상태 Developer Preview — 프로덕션 비권장 · aipub은 제품 이식이 아닌 패턴 차용 관점.
02레이어 · 포지셔닝

AI 팩토리 속 NVCM의 위치

NVCM은 네트워크 스위치 구성 레이어 · AIPub은 그 위 k8s 플랫폼 레이어 — 서로 다른 층.

  • NVCM 진입점 = ② — 스위치 HW·케이블은 이미 있는 상태(①)에서 그 스위치의 OS·config를 자동화
  • Day-0는 AI 팩토리 전체가 아니라 스위치가 처음 부팅되는 시점 (레이어마다 각자의 Day-0가 있음)
  • NVCM ≠ AIPub — 층이 다름(②↔④) · 직접 얽히지 않음 → 제품이 아닌 패턴만 차용

04렌더 흐름

변경이 생기면 자동으로 다시 만든다

사람이 인벤토리를 고치면, 나머지는 자동으로 흘러간다.

  • 인벤토리를 바꾸면 → 관련 장비 설정만 다시 만들어져 → 새 버전으로 저장
  • 변경이 있을 때만 반응(평소엔 대기) · 동시에 여러 변경이 와도 꼬이지 않게 순서 보장

07아키텍처

이벤트 기반 마이크로서비스

기능별로 나뉜 여러 서비스가 메시지 브로커(NATS)를 통해 이벤트로 통신한다.

  • 서비스끼리 직접 호출하지 않고 이벤트로 통신 → 느슨한 결합, 한 서비스 장애가 전체로 번지지 않음
  • 모든 상태는 DB·캐시에 저장 · 진실의 근원은 Nautobot(SoT) 하나로 일원화

08핵심 설계

Config Store — 불변 버전

렌더 결과를 절대 덮어쓰지 않고 새 버전으로만 쌓는다.

  • intended / backup 두 타입, 버전 자동 증가 (v1 →)
  • 불변 — 수정 없이 새 버전만 → 완전한 감사 추적
  • SHA256 content hash로 중복 제거 · 버전간 diff · 1년 보관
  • FastAPI REST + OpenAPI · Redis 캐시 (cache refresh service)
감사·롤백·재현을 기본 확보 · aipub 차용 후보 ①.
출처 · https://github.com/NVIDIA/nv-config-manager/blob/main/docs/config-store/config-store-architecture.mdx

불변 렌더 이력 저장소

현재 aipub — reconcile 결과를 k8s에 현재 상태만 apply.

  • → reconcile가 만든 manifest 스냅샷을 불변 버전 저장
  • 누가·언제·무엇을 감사 + 특정 버전으로 롤백
  • SHA256 dedup · 버전간 diff는 그대로 차용 가능
  • 구현: 외부 DB 없이 Revision CRD 또는 status.history 로 적용 가능할 듯
Config Store 패턴을 status.renderedRevision · history · drift 로.
aipub 적용 · ②

민감 작업 승인 게이트

위험한 변경엔 사람 승인을 강제.

  • 대상: Quota 대폭 증설 · Project 삭제 · 리소스 회수
  • NVCM의 Temporal 승인 워크플로 = human-in-the-loop
  • k8s에선 Argo Workflows 또는 승인 CRD + admission webhook
"바로 적용" → "승인 후 적용" 안전장치.
